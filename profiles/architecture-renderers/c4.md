# C4 Model

Quatro níveis de zoom: Contexto, Container, Componente, Código. Cada nível responde a uma
pergunta diferente, para um público diferente.

## Quando e a escolha certa

- há públicos distintos: executivo quer Contexto, desenvolvedor quer Componente
- o sistema tem fronteiras que precisam ficar explicitas
- a arquitetura vai ser explicada mais de uma vez, para gente diferente

## Os níveis

| Nivel | Responde | Para quem |
|---|---|---|
| 1 · Contexto | o sistema e quem fala com ele | qualquer um |
| 2 · Container | as peças executáveis e como se falam | técnico |
| 3 · Componente | o que há dentro de um container | quem vai implementar |
| 4 · Código | classes e relações | raramente vale a pena |

O nível 4 quase nunca compensa: envelhece a cada commit. Gere sob pedido explicito.

## Como aplicar a notação

Renderiza em Mermaid. A paleta BKS mapeia nos elementos do C4:

| Elemento C4 | Cor BKS |
|---|---|
| sistema em foco | azul backend |
| sistema externo | cinza externo |
| banco de dados | verde storage |
| fila ou topico | laranja broker |
| pessoa ou canal | vermelho acesso |

Fronteira de sistema vira `subgraph`.

## Limite honesto

Um diagrama por nível. Misturar níveis produz o diagrama que não serve a ninguém — nem geral o
bastante para o executivo, nem detalhado o bastante para quem implementa.
